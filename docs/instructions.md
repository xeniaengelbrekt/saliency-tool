# Инструкция для автора проекта

Рабочий документ: как устроен проект, как его проверять, выпускать версии и получать DOI.
Описание алгоритмов и формул — в [`methods.md`](methods.md), список изменений — в [`../CHANGELOG.md`](../CHANGELOG.md).

---

## Что есть сейчас (версия 1.1.x)

- **Основной модуль** `salience.html`: анализ одного стимула, сравнение (несколько изображений и составной
  стимул 2×1 / 1×2 / 2×2 с автоматическим исключением белых полей), подбор наборов (несколько метрик,
  непересекающиеся наборы, ANOVA).
- **Айтрекинг-модуль** `eyetracking.html`: CC, NSS, AUC-Judd, sAUC, SIM, KL; центральный baseline и
  split-half предел; метрики по участникам; пакетный расчёт; учёт положения стимула на экране.
- **Четыре алгоритма**: FT, DoG, Local Contrast, SR; семь метрик; справка внутри приложения («Помощь»).
- **Автотесты**: 47 проверок вычислительного ядра (`tests/`), запускаются в браузере и на GitHub.
- Живая версия: https://xeniaengelbrekt.github.io/saliency-tool/

## Как устроен репозиторий

| Путь | Назначение |
|---|---|
| `index.html`, `fixations.html`, `css/`, `js/` | исходники (ES-модули), править **их** |
| `salience.html`, `eyetracking.html` | собранные одиночные файлы; **не править вручную**, собираются `py build.py` |
| `build.py` | сборка двух одиночных файлов из исходников |
| `tests/` | автотесты (`tests/index.html` — в браузере, `tests/run-node.js` — в Node) |
| `validation/` | сверка с независимой реализацией на Python (см. `validation/README.md`) |
| `start.bat` | локальный сервер для разработки (нужен Python): `http://localhost:8765/` |
| `docs/` | документация |
| `CITATION.cff`, `.zenodo.json` | метаданные для цитирования и Zenodo |
| `.github/workflows/tests.yml` | автопроверка при каждой загрузке на GitHub |

## Как вносить изменения

1. Отредактировать файлы в `js/`, `css/`, `index.html` или `fixations.html`.
2. Запустить сервер (`start.bat`), открыть `http://localhost:8765/tests/` — все тесты должны быть зелёными.
   Если меняется формула — обновить эталонные числа в блоке «регрессия» в `tests/tests.js` **осознанно**
   и записать изменение в `CHANGELOG.md`.
3. Пересобрать одиночные файлы: `py build.py`.
4. Загрузить на GitHub (через git или веб-интерфейс). GitHub Actions проверит тесты и то, что
   одиночные файлы соответствуют исходникам; Pages пересоберёт сайт за 1–3 минуты.
5. На сайте нажать Ctrl+F5 (иначе браузер может показать старые скрипты из кэша).

Тесты в Node (если он у вас установлен): `node tests/run-node.js`.

Если менялись формулы алгоритмов или метрик, дополнительно выполните сверку с независимой
реализацией (`validation/README.md`) и убедитесь, что расхождения не выросли.

## Выпуск версии и получение DOI (Zenodo)

DOI нужен для цитирования инструмента в статье: рецензент спросит, где код и какая версия использовалась.
Zenodo бесплатно архивирует каждый релиз GitHub и присваивает ему DOI.

**Делается один раз:**
1. Зайти на https://zenodo.org → «Log in» → **Log in with GitHub**, разрешить доступ.
2. Открыть https://zenodo.org/account/settings/github/ , найти `saliency-tool` и включить переключатель (**ON**).
   Это нужно сделать **до** создания релиза — иначе Zenodo его не увидит.

**Для каждой версии:**
1. Убедиться, что изменения загружены в ветку `main`, тесты на GitHub зелёные.
2. На GitHub: репозиторий → справа **Releases** → **Create a new release**.
3. **Choose a tag** → ввести `v1.1.4` (создать новый тег) → Target: `main`.
4. Название: `Saliency 1.1.4`; описание — скопировать раздел версии из `CHANGELOG.md`.
5. **Publish release**.
6. Через 1–2 минуты на странице Zenodo (шаг 2 выше) у репозитория появится значок с DOI. На странице записи
   можно найти два DOI: **DOI версии** (ссылается на конкретный релиз — его указывают в статье, чтобы результаты
   воспроизводились) и **DOI концепции** (всегда ведёт на последнюю версию).
7. Вписать DOI в `README.md` (раздел «Цитирование») и `CITATION.cff` (поле `doi`), загрузить на GitHub обычным
   способом. Новый релиз для этого не нужен.

Метаданные записи (название, автор, лицензия, ключевые слова) берутся из `.zenodo.json`. Если нужно добавить
организацию или ORCID — отредактировать этот файл **до** публикации релиза (в записи после публикации автор
можно поправить вручную на сайте Zenodo).

## Если что-то сломалось

1. **Сайт показывает старую версию** — Ctrl+F5; проверьте вкладку **Actions** в репозитории: сборка Pages должна
   завершиться успешно.
2. **Тесты на GitHub упали** — открыть вкладку **Actions** → упавший запуск → шаг «Тесты»: там написано, какая
   проверка не прошла и что ожидалось.
3. **Одиночные файлы не соответствуют исходникам** (упала проверка «бандлы актуальны») — выполнить `py build.py`
   и загрузить обновлённые `salience.html` и `eyetracking.html`.
4. **Файл `salience.html` не открывается** — другой браузер (Chrome, Firefox, Edge, Safari); запасной вариант —
   `start.bat` (нужен Python).
5. **Не ясно, что означает метрика** — «Помощь» в правом верхнем углу приложения или [`methods.md`](methods.md).
