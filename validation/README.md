# Сверка с независимой реализацией

Проверка того, что JavaScript-код считает то же, что независимо написанный код на Python
(numpy, scipy, OpenCV). Это проверка **корректности вычислений**, а не предсказательной силы моделей.

## Как воспроизвести

1. Создать эталон (нужны numpy, scipy, opencv-python; есть, например, в составе PsychoPy):

   ```
   python validation/make_reference.py --dir папка_с_изображениями
   ```

   или перечислить файлы: `--images a.jpg b.png …`. Результат — `validation/data/reference.json`
   (в репозиторий не входит).
2. Запустить сервер (`start.bat`) и открыть `http://localhost:8765/validation/compare.html`.
   Страница прогоняет те же пиксели через JS-код и выводит расхождения; итог доступен в
   `window.__validation`.

Изображения в репозиторий не включены (лицензии). Фиксации синтетические: 8 «участников» по 20 фиксаций,
70 % — из плотности, пропорциональной квадрату карты FT, 30 % — центральное смещение; фиксации нескольких
изображений служат негативами для sAUC.

## Что сравнивается

| Величина | JS-код | Эталон |
|---|---|---|
| Lab-преобразование (FT) | `rgbToLab` | `cv2.cvtColor(..., COLOR_RGB2Lab)` |
| Размытие | разделяемое ядро, clamp-to-edge | `scipy.ndimage.gaussian_filter(mode='nearest')`, `cv2.filter2D(BORDER_REPLICATE)` |
| БПФ (SR) | собственный radix-2 | `numpy.fft` |
| Сжатие до 64×64 (SR) | усреднение по площади | `cv2.INTER_AREA` |
| Увеличение карты (SR) | билинейное, по центрам | `cv2.INTER_LINEAR` |
| Метрики соответствия | `fixmap.js` | numpy по определениям (AUC-Judd — с разрешением ничьих случайным шумом 10⁻⁷, усреднение по 20 повторам; sAUC — `scipy.stats.mannwhitneyu`) |
| ANOVA, квантили t, ДИ, CDF F | `stats.js` | `scipy.stats` |

## Результаты сверки с независимой реализацией (версия 1.1.3, 8 фотографий: 256×256, 256×192, 256×171, 256×128)

Карты салиентности (после нормировки):

| Метод | r (мин.) | макс. \|Δ\| карты | peak JS / эталон |
|---|---|---|---|
| FT | 0.99998 | 5·10⁻³ | 0.999 … 1.002 |
| DoG | 1.00000 | 7·10⁻⁷ | 1.000 |
| Local Contrast | 1.00000 | 7·10⁻⁴ | 1.000 |
| SR | 1.00000 | 3·10⁻⁶ | 1.000 |

Наибольшее расхождение у FT; его причина отдельно не исследовалась (вероятно, различия реализаций
преобразования в Lab). До версии 1.1.3 у SR расхождение достигало 0.10 (r = 0.9957 на изображении 256×171)
из-за неравномерного сжатия при нецелом отношении размеров и привязки увеличения к углам пикселей.

Метрики карты — максимальное относительное расхождение по 8 изображениям:

| Метод | mean | peak | entropy | center_bias | spread_pct | peak_x | peak_y |
|---|---|---|---|---|---|---|---|
| FT | 0.25 % | 0.24 % | 0.33 % | 0.50 % | 1.1 % | 0.37 % | 1.7 % |
| DoG | 0.03 % | 0.04 % | 0.10 % | 0.39 % | 0.09 % | 0.01 % | 0.02 % |
| Local Contrast | 0.07 % | 0.03 % | 0.13 % | 0.41 % | 0.48 % | 0.01 % | 0.03 % |
| SR | 0.02 % | 0.03 % | 0.11 % | 0.72 % | 0.35 % | 0.72 % | 0.15 % |

Метрики соответствия — максимальное абсолютное расхождение (модель FT / центральный baseline):

| CC | NSS | AUC-Judd | sAUC | SIM | KL |
|---|---|---|---|---|---|
| 1.4·10⁻³ / 1·10⁻⁹ | 1.2·10⁻³ / 8·10⁻⁹ | 5.4·10⁻⁴ / 1.1·10⁻⁴ | 2.4·10⁻⁴ / 0 | 2.7·10⁻⁴ / 8·10⁻¹⁰ | 4.6·10⁻⁴ / 2.5·10⁻⁹ |

Расхождения FT-модели — следствие расхождения самих карт FT (первая таблица); для центрального baseline,

Статистика: F ANOVA — 4·10⁻¹⁶, p — 4·10⁻¹⁶, квантиль t (df = 1…100) — 3·10⁻¹⁰, границы 95 % ДИ — 4·10⁻¹⁶,
CDF F-распределения — 7·10⁻¹⁶ (абсолютные расхождения).

## Сверка с внешними реализациями (версия 1.1.4)

Запуск: `python validation/compare_external.py --pysaliency-src <папка pysaliency>`; перед этим открыть
`validation/compare_external.html` и сохранить выведенный JSON в `validation/data/js_identical.json`.
Нужны numpy, scipy, numba и opencv-contrib-python; исходный код pysaliency (sdist с PyPI) достаточно
распаковать — ставить пакет целиком не требуется (для него нужен C-компилятор), используются только
`metrics.py` и `numba_utils.py`.

**Метрики соответствия против pysaliency 0.2.22** (Kümmerer et al.; библиотека реализует метрики
MIT/Tübingen Saliency Benchmark). Одинаковые входные данные: карта модели, карта плотности фиксаций,
пиксели фиксаций и негативов sAUC; 8 изображений × 2 модели (FT и центральный baseline).

| CC | NSS | AUC-Judd | sAUC | SIM | KL |
|---|---|---|---|---|---|
| 2.7·10⁻¹⁰ | 1.1·10⁻¹⁴ | 4.4·10⁻¹⁶ | 1.1·10⁻¹⁶ | 2.4·10⁻¹⁰ | 7.5·10⁻¹⁰ |

(максимум \|Δ\|, JS − pysaliency). Результаты совпадают до машинной точности. Замечания: AUC-Judd сравнивался
с `general_roc_numba(judd=1)` при негативах «нефиксированные пиксели» (определение Judd); в
pysaliency по умолчанию негативы — все пиксели, что даёт отличие до 9·10⁻⁴. sAUC у pysaliency (`judd=0`) —
то же, что статистика Манна — Уитни, как и в инструменте.

**SR против OpenCV-contrib 4.11.0** (`cv2.saliency.StaticSaliencySpectralResidual`):

| Сравнение | r (мин.) | r (медиана) |
|---|---|---|
| карта инструмента ↔ карта OpenCV (напрямую) | 0.391 | 0.551 |
| карта инструмента, пересчитанная шагами OpenCV («как в OpenCV») ↔ карта OpenCV | 0.9997 | 0.9999 |
| способ сжатия до 64×64 (площадь ↔ билинейное), при сглаживании σ = 8 | 0.925 | 0.962 |

Прямое совпадение умеренное, потому что реализации различаются итоговым сглаживанием: OpenCV применяет
`GaussianBlur` с ядром 5×5 (при σ = 8 это почти равномерное усреднение 5×5 на сетке 64×64) до возведения
в квадрат, а оригинальная статья (и инструмент) — гауссиан σ = 8 на всей сетке. Если воспроизвести шаги
OpenCV, получается его карта (r ≥ 0.9997), то есть остальные шаги (БПФ, фаза, спектральный остаток)
согласованы. Следствие: **карты SR из инструмента и из OpenCV нельзя считать взаимозаменяемыми**; результат
SR также заметно (r ≈ 0.93–0.99) зависит от способа сжатия до 64×64.

## Быстродействие

Карта и метрики на рабочей копии 256 px (Chromium 152, Windows 11, 8 логических ядер, один поток; среднее ± SD по 30 расчётам):
FT 60 ± 13 мс, SR 28 ± 4 мс, DoG 291 ± 56 мс, Local Contrast 299 ± 44 мс. Полный расчёт соответствия одного стимула с
160 фиксациями (карта, карта фиксаций, шесть метрик для модели и baseline, split-half по 10 разбиениям, метрики по
участникам): 2.8 ± 0.04 с.

## Ограничения сверки

- Эталон написан тем же автором, что и JS-код: общая ошибка в понимании формулы не была бы обнаружена.
  Независимость — в библиотечных реализациях, а не в постановке.
- Не выполнена проверка на открытых датасетах реальных фиксаций (значения классических моделей
  не сопоставлялись с опубликованными).
- Фиксации синтетические: проверяется совпадение расчётов, а не качество предсказаний.
