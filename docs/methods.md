# Методы и формулы

Точное описание того, что считает инструмент (версия 1.1.x). Каждое утверждение
здесь проверяется автотестами (`tests/tests.js`) либо указано как допущение.

## 1. Подготовка изображения

Изображение приводится к рабочей копии с длинной стороной 256 px, **пропорции сохраняются**
(`workSize`: `k = 256 / max(W, H)`, минимум 8 px по короткой стороне). Сжатие — сглаживание canvas
браузера (`imageSmoothingQuality = 'high'`). Все карты имеют размер рабочей копии; при экспорте
масштабируются обратно в исходное разрешение тем же сглаживанием.

## 2. Алгоритмы карты салиентности

Обозначения: `I` — изображение, `S` — сырая карта, `Ŝ` — нормированная карта ([0, 1]).

**FT — Frequency-Tuned** (Achanta et al., 2009).
`S(x, y) = ‖ I_μ − I_ω(x, y) ‖₂`, где `I_μ` — средний вектор CIE Lab по изображению,
`I_ω` — Lab-изображение, размытое биномиальным ядром 5×5 (`[1 4 6 4 1]/16`, по осям раздельно,
на краях — продолжение крайнего значения). sRGB → Lab: линеаризация, матрица sRGB→XYZ (D65),
белая точка (0.95047, 1, 1.08883). Использует цвет.

**DoG — Difference of Gaussians.**
`S = Σ_{(σ₁, σ₂)} | G_{σ₁} * L − G_{σ₂} * L |` по парам (1, 2), (2, 4), (4, 8), (8, 16) px
рабочей копии; `L` — яркость Rec. 601 (шкала 0–255). Цвет не использует.

**Local Contrast.**
`S = Σ_{c ∈ {R,G,B}} ( c − G_σ * c )²`, `σ = 0.08 · max(W, H)`, каналы в шкале 0–1.

**SR — Spectral Residual** (Hou & Zhang, 2007).
Яркость сжимается до 64×64 усреднением по площади (вес пикселя — доля покрытия, как у `cv2.INTER_AREA`); `F = FFT₂(L)`; `A = |F|`, `P = arg F`;
`𝓛 = ln A`; `R = 𝓛 − box₃ₓ₃(𝓛)`; `S = | FFT₂⁻¹( exp(R + iP) ) |²`; затем гауссово размытие σ = 8
на сетке 64×64 и билинейное увеличение (по центрам пикселей) до размера рабочей копии. Цвет не использует.

## 3. Нормировка

`Ŝ = clip( (S − min S) / (S₀.₉₉₉ − min S), 0, 1 )`, где `S₀.₉₉₉` — 99.9-й перцентиль. Если карта почти
плоская (перцентиль не больше минимума) — обычная min–max нормировка; если `max = min` — нулевая карта.
К карте прикреплены `rawMin`, `rawMax` (истинный максимум — для метрики peak), `rawHi`.

**Следствие:** mean, spread, entropy — характеристики *формы* карты внутри одного изображения,
абсолютный уровень контраста в них не входит. Сравнивать стимулы по ним можно; абсолютную силу
контраста несёт только `peak` (и только в пределах одного метода).

## 4. Метрики карты (`computeMetrics`)

| Метрика | Определение |
|---|---|
| `mean` | `ΣŜ / N` |
| `peak` | `max S` до нормировки (4 значащие цифры) |
| `entropy` | `−Σ pᵢ log₂ pᵢ` по гистограмме из 64 бинов значений `Ŝ` (максимум 6 бит) |
| `center_bias` | `mean(Ŝ внутри эллипса) / mean(Ŝ вне эллипса)`; эллипс с центром в центре кадра и полуосями `0.7·W/2`, `0.7·H/2` (≈ 38.5 % площади при любых пропорциях) |
| `spread_pct` | `100 · #{Ŝ > 0.5} / N` (порог условный) |
| `peak_x`, `peak_y` | центр масс пикселей со значением `max Ŝ`, по центрам пикселей, % от ширины/высоты |

**Корреляция карт** (`pearsonR`): коэффициент Пирсона по пикселям. Карты разного размера (или
одинаковой площади, но разной формы, например 256×144 и 144×256) приводятся билинейно к общей
сетке 128×128, то есть сравниваются в относительных координатах кадра.

## 5. Составной стимул

Карта считается один раз по всему изображению. Ячейки сетки (2×1, 1×2, 2×2) вырезаются из карты
**без перенормировки**, поэтому метрики регионов на общей шкале. `share_r = 100 · Σ_{r} Ŝ / Σ Ŝ` —
доля салиентности региона (при равной заметности: 100 % / число регионов; доли — композиционные
данные, при анализе используйте лог-отношения).

**Поля.** Цвет фона — медиана внешней рамки изображения (2 px); фон признаётся, только если ≥ 90 %
пикселей рамки в пределах 20 уровней канала от медианы (прозрачные считаются фоном). В каждой ячейке
строка/столбец — содержимое, если ≥ 1.5 % их пикселей отличаются от фона более чем на 20 уровней;
прямоугольник от первой до последней такой строки/столбца — картинка. Если она занимает > 97 % или
< 3 % ячейки — поля не найдены. Перед расчётом всё вне картинок заливается средним цветом картинок,
после — обнуляется; метрики и доли считаются по картинкам.

## 6. Подбор наборов

Каждая выбранная метрика (`mean`, `spread_pct`, `entropy`, `center_bias`) z-нормируется по всем
загруженным изображениям. Стоимость комбинации (по одному изображению из каждой группы) —
сумма по метрикам *популяционной* дисперсии z-оценок внутри комбинации. Перебор полный.
`K = 1` → топ-5 комбинаций (могут пересекаться). `K > 1` → жадно: лучшая комбинация, её изображения
исключаются, поиск повторяется; глобальный оптимум разбиения не гарантируется. Для итоговых K наборов —
однофакторный ANOVA между группами по каждой метрике (F, p, η²; p через неполную бета-функцию).
Незначимый ANOVA не доказывает равенства (для этого нужен тест эквивалентности).

## 7. Сравнение с айтрекингом

**Координаты.** Фиксация `(x, y)` в системе экрана → `u = (x − x₀)/w`, `v = (y − y₀)/h`, где
`(x₀, y₀, w, h)` — прямоугольник стимула (по центру экрана / растянут с сохранением пропорций /
вручную / координаты уже в пикселях изображения). `0 ≤ u, v < 1` → фиксация попала в стимул, ячейка
сетки `⌊u·gw⌋, ⌊v·gh⌋`; остальные не учитываются и подсчитываются отдельно. Координаты в долях 0–1
умножаются на размер экрана (или изображения).

**Карта фиксаций.** Сумма дельта-функций (вес = 1, опционально — длительность), свёртка с гауссианом
`σ` (в единицах координат айтрекера; по осям пересчитывается отдельно), нулевое дополнение на краях.
Для CC и показа — нормировка как в п. 3; для SIM и KL — нормировка на сумму 1.

**Метрики** (определения MIT/Tuebingen Saliency Benchmark):
- CC — корреляция Пирсона карты салиентности и карты фиксаций;
- NSS — среднее значение `(S − μ_S)/σ_S` в точках фиксаций;
- AUC-Judd — ROC-кривая по порогам, равным значениям карты в фиксированных пикселях; TPR — доля
  фиксаций выше порога, FPR — доля нефиксированных пикселей выше порога; пиксели с равным значением
  проходят порог одновременно (плоская карта даёт 0.5); каждая фиксация учитывается отдельно;
- sAUC — негативы: места фиксаций на других стимулах того же CSV; считается точно (статистика
  Манна — Уитни, равные значения — ½);
- SIM — `Σ min(Pᵢ, Qᵢ)`; KL — `Σ Qᵢ ln(ε + Qᵢ/(Pᵢ + ε))`, `Q` — фиксации, `P` — модель.

**Ориентиры.** *Центральный baseline* — гауссиана в центре кадра, σ = W/4, H/4. *Согласованность
участников (split-half)* — участники 10 раз случайно делятся пополам (ГПСЧ с фиксированным зерном),
карта одной половины оценивается по фиксациям другой, в обе стороны; результат — среднее. По половине
выборки оценка слегка занижена. *По участникам* — NSS, AUC, CC для каждого участника; среднее и 95 % ДИ
(t-распределение). В пакетном режиме — среднее и 95 % ДИ по стимулам.

**Разбор CSV.** Разделитель `;`, `,` или табуляция; кавычки и переносы внутри кавычек; колонки по
целым словам названия и списку известных имён (Tobii Pro Lab, GazePoint, EyeLink Data Viewer, простой
формат); ручной выбор. Тип события: пусто или начинается с «fix»/«фикс» — фиксация. Повторы в покадровых
выгрузках: по номеру фиксации (вместе с участником и стимулом), иначе — подряд идущие строки с теми же
участником, стимулом и координатами.

## 8. Допущения и ограничения

- Модели низкоуровневые: семантика, задача и инструкция не учитываются.
- Пороги интерпретаций в справке (например, «типичная фотография» для mean) — ориентиры, а не нормы.
- Порог `spread` = 0.5 условный.
- Значения `peak` разных методов несопоставимы.
- Подбор с K > 1 жадный.
- Работа на рабочей копии 256 px: мелкие детали (особенно для SR с 64×64) теряются.
- Поиск полей в составном стимуле требует однородного фона; на неоднородном фоне поля не ищутся.

## 9. Проверка

Три уровня (подробные числа — в [`../validation/README.md`](../validation/README.md)).

**1. Автотесты** (`tests/tests.js`, 47 проверок; браузер: `start.bat` → `/tests/`, Node ≥ 18:
`node tests/run-node.js`; на GitHub — при каждой загрузке): точные значения (цвет в Lab, ANOVA, квантили,
AUC плоской карты = 0.5, NSS/sAUC/SIM/KL на известных картах), независимые реализации внутри теста
(наивная 2D-свёртка, наивное ДПФ, FT «в лоб» по формулам из литературы), свойства (зеркальная симметрия,
независимость от пропорций кадра, инвариантность SR к кратному увеличению), парсинг CSV Tobii /
GazePoint / EyeLink и регрессионные эталоны на фиксированной сцене.

**2. Сверка с независимой реализацией на Python** (`validation/make_reference.py` + `validation/compare.html`):
те же карты и метрики считаются на numpy / scipy / OpenCV (другие реализации Lab-преобразования,
гауссова размытия, БПФ, статистики), результаты сравниваются с JavaScript-кодом на реальных
фотографиях разных пропорций. Сверка нашла и позволила исправить две неточности в SR (сжатие при нецелом
отношении размеров и привязка увеличения к углам, а не к центрам пикселей).

**3. Не выполнено:** сверка с внешними эталонными реализациями (OpenCV-contrib, код MIT benchmark) и
проверка на открытых датасетах фиксаций — см. план статьи.
