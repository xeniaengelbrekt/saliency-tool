В порядке приоритета:

1. **Открыть `salience.html`, прогнать на своих стимулах, обкатать интерфейс.**

2. **Выгрузить ретроспективу по своему 4-картинному исследованию.**
   Загрузить старые стимулы в Режим 2 → составной стимул (2×2). Получить таблицы метрик и попарные корреляции. Сохранить CSV. Это даст материал для физиологической статьи (раздел самокритики).

3. **Решить, в какие журналы целишь.**
   Это влияет на стиль и оформление статей. Когда решишь — скажи названия, я переоформлю статьи под их требования к ссылкам и аннотации.

4. **GitHub + DOI** (см. ниже подробно).

## Подготовка к публикации: GitHub + DOI

Без этого статья тяжело пройдёт рецензию: рецензент задаст вопрос «где код?» и попросит указать постоянный идентификатор инструмента.

### Шаг 1. Создать аккаунт GitHub

Если уже есть — пропустить. Если нет — `https://github.com/signup`, бесплатно.

### Шаг 2. Создать репозиторий

1. Войти на GitHub, нажать «New repository».
2. Имя: `saliency-tool` или `vis-saliency-browser` или как угодно. Без русских букв в имени репозитория.
3. Visibility: **Public**.
4. Поставить галку «Add a README file».
5. License: **MIT** (стандартный выбор для научного ПО, разрешает использование с указанием автора).
6. Создать.

### Шаг 3. Залить файлы

Самый простой способ — через веб-интерфейс GitHub:

1. На странице репозитория нажать «Add file» → «Upload files».
2. Перетащить из `D:\салиентность\` всё содержимое: `salience.html`, `index.html`, папки `css`, `js`, `docs`, файл `build.py`, `start.bat`.
3. Внизу написать в коммит: «Initial release» и нажать «Commit changes».

Если будешь много дорабатывать — есть смысл поставить GitHub Desktop (графический клиент), но для первой загрузки веб-интерфейса хватит.

### Шаг 4. Написать README

В корне репозитория откроется автоматически созданный `README.md`. Заменить его содержимое на что-то вроде (могу сгенерировать готовый — скажи, и сделаю в `docs/README-template.md`):

```markdown

Инструмент для контроля низкоуровневых визуальных свойств стимулов
в исследованиях зрительного восприятия. Работает в браузере без установки.

## Запуск
Откройте `salience.html` двойным кликом.

## Что внутри

- 7 метрик с обучающим эксплейнером
- Сравнение карт через корреляцию Пирсона
- Автоматический подбор сбалансированных наборов

## Цитирование
Если использовали в публикации, ссылайтесь как:
[ваше ФИО, год публикации статьи, журнал]

## Лицензия
MIT
```

### Шаг 5. Создать DOI через Zenodo

Это нужно для цитируемости. Делается один раз и навсегда.

1. Зайти на `https://zenodo.org`, войти через GitHub (кнопка вверху).
2. Открыть страницу `https://zenodo.org/account/settings/github/`.
3. Найти свой репозиторий в списке, переключить тумблер в положение **ON**. Это включает автоматическую архивацию релизов.
4. Вернуться на GitHub, в репозиторий → справа «Releases» → «Create a new release».
5. Tag version: `v1.0.0`. Title: `Saliency 1.0.0 — initial release`. Description: коротко, что это.
6. Нажать «Publish release».
7. Через 1–2 минуты Zenodo подхватит релиз и создаст для него DOI. Найти его можно в `https://zenodo.org/account/settings/github/` рядом с репозиторием — ссылка-бэйдж с DOI.
8. Скопировать DOI (вида `10.5281/zenodo.NNNNNNN`).

DOI вставить в обе статьи в раздел «Доступность инструмента» вместо плейсхолдера.

## Перед подачей в журналы

### Психологическая статья

1. **Литобзор.** В файле `docs/article-psychology.md` на месте `[ЗДЕСЬ ЛИТОБЗОР: ...]` написать обзор. Минимум: Itti–Koch 1998, Treisman–Gelade 1980 (feature integration theory), Henderson 2003 (свободный просмотр), Tatler 2007 (центральный сдвиг), Borji–Itti 2013 (обзор моделей), 1–2 свежих метрики оценки моделей.

2. **Своё исследование.** Раздел `[ЗДЕСЬ ОПИСАНИЕ ВАШЕГО ИССЛЕДОВАНИЯ ...]` — кратко: парадигма, что мерилось, какой эффект, что показывает ретроспективный анализ салиентности.

3. **Заключение** — 3–5 пунктов выводов, можно по образцу заглушки.

4. **УДК и аффилиации** — если журнал требует.

5. **Английская аннотация и ключевые слова** — обычно требуют. Скажи, я переведу.

### Физиологическая статья

То же самое, но в `docs/article-physiology.md`. Ключевое отличие — раздел самокритики:

1. **Не пытайся обесценить старую работу.** Формулировки вроде «обнаруженный эффект полностью объясняется салиентностью» — нет. Только «дополнительный источник вариативности», «не позволяет полностью исключить альтернативную интерпретацию», «требует уточнения в последующих работах».

2. **Дай конкретные цифры.** Не «стимулы плохо сбалансированы», а «дисперсия средней салиентности между четырьмя элементами стимула в условии А составила X, в условии Б — Y, что соответствует …».

3. **Сформулируй методические рекомендации.** Не «впредь надо контролировать», а конкретно: какие метрики проверять, на каких порогах принимать решения, что включать в supplementary.

## Глоссарий своего проекта

Чтобы через полгода не путаться:

- `D:\салиентность\` — корень проекта.
- `salience.html` — собранный single-file билд для распространения. Это то, что отдаёшь коллегам.
- `index.html` + `css/` + `js/` — модульный исходник для разработки. Менять только если хочешь дописывать функциональность.
- `build.py` — скрипт сборки `salience.html` из исходников. Запуск: `py build.py` в папке проекта.
- `start.bat` — запасной запуск через локальный сервер (если `salience.html` где-то откажется).
- `docs/` — документация и куски статей.
- `docs/article-psychology.md` — психологическая статья.
- `docs/article-physiology.md` — физиологическая.
- `docs/instructions.md` — этот файл.

1. **Не открывается `salience.html`** — попробуй другой браузер (Chrome / Firefox / Edge / Safari). Если совсем никак — двойной клик по `start.bat` запустит локальный сервер (нужен Python).

2. **Какие-то правки сломали интерфейс** — у тебя есть резервная копия в виде Git-истории на GitHub. Нажми «History» на нужном файле, восстанови предыдущую версию.

3. **Не понятно, что значит метрика / метод** — открой инструмент → «Помощь» в правом верхнем углу. Там есть всё.

4. **Возникли вопросы, которые не нашлись в «Помощи»** — пиши мне, добавим в руководство.
