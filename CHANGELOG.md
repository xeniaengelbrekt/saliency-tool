# Изменения

## 1.1.3 — 2026-09-30

- **SR: две неточности исправлены** (найдены сверкой с независимой реализацией на Python):
  сжатие до 64×64 при нецелом отношении размеров (например, 171 → 64) усредняло блоки неравномерно,
  а увеличение карты привязывало углы, а не центры пикселей (карта была чуть растянута).
  Теперь сжатие — усреднение по площади, увеличение — билинейное по центрам пикселей.
  Расхождение с эталоном по карте SR: макс. |Δ| 0.10 → 3·10⁻⁶. Метрики SR изменились
  (у «типичных» изображений — на единицы процентов; сильнее всего — у изображений, размер рабочей копии
  которых не кратен 64). Результаты, посчитанные методом SR до 1.1.3, следует пересчитать.
- **Сверка с независимой реализацией** (`validation/`): скрипт на numpy/scipy/OpenCV и страница
  сравнения; карты FT, DoG, Local Contrast, SR и метрики соответствия совпадают с эталоном
  (r ≥ 0.99998; метрики соответствия — до 1.4·10⁻³).
- Тесты: 47 (добавлены инвариантность SR к увеличению и нецелое отношение размеров).

## 1.1.2 — 2026-09-30

  без приведения к общей сетке. Ошибка найдена новыми автотестами. Затрагивала только матрицу корреляций

- **Сборка воспроизводима:** `build.py` всегда пишет LF (раньше на Windows получались CRLF, и результат
  зависел от системы); добавлен `.gitattributes`.
- **Автотесты** (`tests/`): 45 проверок ядра — точные значения, независимые реализации (FT, свёртка,
  ДПФ), свойства (зеркальная симметрия, независимость от пропорций), парсинг CSV, регрессионные эталоны.
  Запуск в браузере и в Node; проверка на GitHub Actions.
- **Документация:** добавлены `docs/methods.md` (алгоритмы и формулы), `CITATION.cff`, `.zenodo.json`;
  `docs/instructions.md` и README приведены в соответствие с проектом (удалены ссылки на отсутствующие
  документы, указан автор).

## 1.1.1 — 2026-09-30

- **Составной стимул: поля вокруг картинок не учитываются.** Если подстимулы вписаны
  в ячейки с однородным фоном (например, белые поля), модуль сам находит картинку
  в каждой ячейке (фон — по внешней рамке изображения). Поля перед расчётом заливаются
  средним цветом картинок, после расчёта обнуляются; метрики и доли считаются только
  по картинкам. Найденные картинки обведены на превью, их координаты есть в CSV.
  Отключается галочкой «Не учитывать поля вокруг картинок».

## 1.1.0 — 2026-09-30

Результаты, посчитанные в 1.0.0, **нужно пересчитать**: изменились формула FT,
нормировка карт, рабочее разрешение и несколько метрик.

### Исправлено — расчёты

- **AUC-Judd завышался.** Пиксели с одинаковой салиентностью сортировались так,
  что фиксации шли первыми: постоянная карта получала AUC = 1.0 вместо 0.5, карта
  с большими нулевыми участками — около 0.9 при случайных фиксациях. Теперь пороги
  берутся по значениям в точках фиксаций, равные значения учитываются одновременно,
  каждая фиксация считается отдельно (как в эталонном коде MIT Saliency Benchmark).
- **Фиксации у правого и нижнего края терялись** (`Math.round` давал индекс 256).
  Теперь координаты переводятся через `floor` с проверкой границ.
- **Изображение сжималось в квадрат 256×256.** Теперь рабочая копия сохраняет
  пропорции (длинная сторона 256 px); SR апскейлится в тот же размер.
- **FT не соответствовал Achanta et al. (2009):** размытие σ ≈ 6.4 px и квадрат
  расстояния. Теперь — биномиальное ядро 5×5 и евклидова норма.
- **Составной стимул:** каждый регион нормировался в [0, 1] отдельно, поэтому все
  регионы выглядели одинаково заметными. Теперь карта считается по всему изображению,
  регионы сравниваются на общей шкале, добавлена доля салиентности региона.
- **Нормировка карт** робастная: верхняя граница — 99.9-й перцентиль, поэтому один
  пиксель-выброс не занижает mean / spread / entropy.
- **peak_x / peak_y** считаются по центрам пикселей и как центр масс вершины.
- **center_bias** считается по эллипсу, повторяющему форму кадра.
- **Корреляция карт разного размера** — через общую сетку 128×128.
- **Local Contrast:** σ = 8 % длинной стороны.

### Исправлено — айтрекинг

- Координаты экрана переводятся в координаты стимула: стимул по центру экрана /
  растянут с сохранением пропорций / прямоугольник вручную; координаты в долях 0–1.
  Размер экрана угадывается по стандартным разрешениям. Фиксации вне стимула
  исключаются и показываются отдельно; на карте айтрекинга отмечены точки фиксаций.
- Если в CSV несколько стимулов, по умолчанию больше не смешиваются фиксации со всех:
  стимул выбирается по имени файла изображения, иначе его нужно выбрать вручную.
- Распознавание колонок — по целым словам, а не по подстроке (раньше колонка
  «Export date» могла стать X). Добавлен ручной выбор колонок.
- Повторы одной фиксации в покадровых выгрузках (Tobii Pro Lab и др.) удаляются —
  по номеру фиксации или по совпадению координат подряд идущих строк.
- Разбор CSV корректно обрабатывает кавычки и переносы строк внутри кавычек.
- Взвешивание по длительности стало опцией (по умолчанию выключено) и применяется
  согласованно к KDE и NSS.
- Края KDE-ядра — нулевое дополнение вместо «прилипания» к границе.

### Добавлено

- Айтрекинг: sAUC (shuffled AUC), SIM, KL; центральный baseline; верхний предел по
  согласованности участников (split-half); метрики по участникам со средним и 95 % ДИ;
  пакетный расчёт по всем стимулам CSV со сводкой по стимулам; расширенные CSV-отчёты.
- Подбор групп: уравнивание по нескольким метрикам (mean, spread, entropy,
  центр/периферия) через z-оценки; K непересекающихся наборов; однофакторный ANOVA
  между группами (F, p, η²) и экспорт этой таблицы в CSV.
- Модуль `js/stats.js`: доверительные интервалы (t-распределение), ANOVA с точным p.
